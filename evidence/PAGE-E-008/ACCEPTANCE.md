- Delivered `/e/notifications` as a mobile employee notification center for task reminders, overdue anomalies, pending ownership approvals, system messages and each employee's private read state. It includes loading, empty, error, forbidden and write-success recovery states.
- Data and access: migration `027_employee_notifications` persists a tenant/employee-bound inbox with a unique source identity. Existing CORE-006 `notification_logs` are materialized idempotently as task/anomaly records; pending customer ownership transfers materialize as approval records. - Writes: marking a notification read verifies the active employee, permission, ownership and optimistic version; it supports `Idempotency-Key` replay and records audit/Outbox data with the `page-e-008` trace.

It verifies unauthenticated/cross-tenant rejection, task/anomaly/approval/system categories, projection de-duplication, category validation, safe-link fallback, private read ownership, idempotency, version conflict, audit and Outbox persistence.
- Browser: `pnpm.cmd exec playwright test --config playwright.page-e-008.config.ts` passes two 390px Chromium flows: an employee opens a real task notification, verifies its task deep link and marks it read; a no-session visitor receives a recovery view. Screenshots: `employee-notifications-mobile.png`, `employee-notifications-forbidden.png`; traces are retained under `playwright-output/`.
