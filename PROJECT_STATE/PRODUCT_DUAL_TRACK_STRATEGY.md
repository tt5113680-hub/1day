## 0. 系统身份（最高优先级 · 一切功能的过滤器）

**我们是谁：** 各大团购平台（美团/抖音/饿了么等）的 **推广员** + 自有 **统一入口分流管理平台**，以 **工具** 身份出现。

**我们只做三件事：**

1. **统一入口**（分流、曝光、进店/进商圈）
2. **统一整合生态**（第三方商品/收银/小程序等外链聚合）
3. **统一工作流管理**（企业与商户工作流整合）

**我们明确不做（禁止竞争）：**

| 禁止 | 含义 |
| ---- | ---- |
| 不碰钱 | 不做收款、分账、资金托管、支付闭环 |
| 不碰销售 | 不做自有货架成交、库存、订单履约 |
| 不碰管理 | 不做替商家经营的进销存/人事/财务等「管店」竞品；管理端只服务入口、整合、工作流与可抓痕迹分析 |

其它能力 **全部用第三方**；与美团/抖音/扫呗等 **只做助力，不产生竞争**。

开发原则仍以 `COMMERCIAL_EXECUTION_CHARTER.md`、模板白名单、诚实边界为准：**统一入口、统一工作流** 写进总纲的，必须全局连动，不得另起第二套产品身份。

## 1. 消费者三面（在「工具」身份下的定义）

### §A 商家消费者首页（= 微站 = 官网，同一首页）

| 项 | 裁决 |
| -- | ---- |
| 关系 | **微站 / 企业官网 / 消费者首页 = 同一个首页**；仅 **UI 模板与功能样式** 不同 |
| UI 型 | 对标美团商家门店页习惯（客户熟悉），不另造体系 |
| 商品 | 全部第三方入口：美团 / 抖音 / **自营=第三方（首选扫呗小程序+收银软件）** / 其它外链 |
| 模板 | 租户可切换行业/微站/官网等样式 → 千店千面（模块白名单装修） |
| 工作流 | 统一工作流整合挂在此入口生态内 |

### §B 附近

| 项 | 裁决 |
| -- | ---- |
| UI 型 | 美团 App 外卖 LBS 首页同型 |
| 范围 | **全平台**：已开通且选择 **「全平台可见引流」** 的租户商家 |
| 动作 | 观看 / 访问 / 跳转（外链）为主 |

### §C 商圈（单独页面 · 商家联盟）

| 项 | 裁决 |
| -- | ---- |
| 页面 | **商圈是单独页面**（不是店页附属块） |
| 租户双身份 | ① **经营者**：可申请、管理 **自己建立的商圈**；② **消费者视角**：可看到 **附近商圈** |
| 商圈经理 | 可自行邀请商家入圈 |
| 商家侧 | 可浏览附近商圈，联系商圈经理申请加入 |
| UI 型 | 类似美团 App 首页：行业分类 + 多栏导航 + LBS 就近活跃 |
| 互助 | 圈内发现合作对象、互相推流（痕迹仍属观看/访问/跳转等） |

## 2. 可抓痕迹与数据分析（主人理解 + 工程补充建议）

> 主人原理解：观看 / 访问 / 跳转 / 停留 / 分享。  
> 下列为在 **推广员工具** 身份下的优化补充：**不扩大到钱/销售/管店**，只把「入口分流是否有效」测准。

### 2.1 三层痕迹（已拍板：L0+L1+L2 一并交付）

> 主人 2026-08-11 12:04：L1+L2 **一起上**，形成完整产品力；相对 L0 增量不大，但成套。

| 层 | 事件 | 说明 | 状态 |
| -- | ---- | ---- | ---- |
| **L0 必抓** | 观看(曝光) / 访问(进页) / 跳转(出站) / 停留 / 分享状态 | 分析最小闭环 | **必做** |
| **L1** | 来源(source/scene/shareCode) · 入口面(附近/店页/商圈/搜索/一码) · 模块位(banner/商品卡/快捷入口…) · 跳转目标平台(美团/抖音/扫呗/外链) · 设备端(H5/PC) · 地理粗粒度(城市或 geohash) · 会话 session_id · 是否回跳/再次访问 | 「从哪来、点了哪、去了哪」 | **与 L0 同批交付** |
| **L2** | 滚动深度 · 关键区块可见(模块曝光去重) · 收藏/咨询点击(站内动作) · 商圈邀约/申请状态变更 · 员工「发出分享」↔消费者「打开分享」配对 · 跳转前确认页完成率 | 装修与互助效果可读 | **与 L0/L1 同批交付** |

**明确不抓（保持不竞争）：** 支付金额、支付成功、第三方订单明细、库存、核销成交额（除非未来第三方只回传「已打开」类状态，且诚实标注非本平台成交）。

### 2.2 漏斗（工具视角，不是销售漏斗）

```text
曝光(观看) → 进页(访问) → 有效停留 → 点击出站(跳转) → [可选]回访/再分享
         ↘ 分享发出 → 被打开 → 再进漏斗
商圈支路：看圈 → 进圈页 → 看商家 → 进店页 → 跳转
```

指标命名对外用 **租户模块名**（如「团购入口」「扫呗收银」），对内用稳定 event code。

### 2.3 分析产品形态（建议）

| 能力 | 做法 |
| ---- | ---- |
| 模块命名看板 | 租户选了哪些入口模块，看板标题/维度跟模块名走 |
| 行业分析模板 | 餐饮/美业/零售等预设「看什么图、什么对比」，仍只基于 L0–L2 |
| 自助分析 | 租户自己拖维度（时间/入口面/平台/商圈）看表 |
| AI 辅助 | 只解读已有痕迹（异常跌涨、哪块入口弱、分享是否带来回访）；**禁止编造成交** |
| 商圈互助维度 | 渠道可标「商家互助平台」= 来源维度，不是销售管理 |

### 2.4 隐私与诚实

- 默认聚合报表；单用户轨迹仅租户授权角色可见且可关。  
- 地理用粗粒度；不做隐蔽持续定位。  
- 凡第三方结果未回传，报表写「仅统计至跳转」，不写「已成交」。

### 2.5 拍板

| 项 | 结论 |
| -- | ---- |
| L0+L1+L2 | **一并上线**，作为完整痕迹分析产品套件（2026-08-11 12:04 主人） |
| 边界 | 仍不碰钱/销售/管店数据 |
| 分析 | 模块命名看板 + 行业模板 / 自助 / AI（只解读 L0–L2） |

## 3. 拍板结论（原 5 问；第 4 点含补充建议待主人点头）

1. **自营** = 第三方平台；首选 **扫呗小程序 + 收银软件**（外链/入口，非 ONEDAY 收单）。  
2. **附近** = 全平台中，已开通且 **全平台可见引流** 的客户商家。  
3. **商圈** = 单独页；租户可建/管自己的商圈 + 以消费者看附近商圈；经理邀约；商家可申请加入。  
4. **数据** = **L0+L1+L2 同批交付**（完整痕迹套件）；分析=模块命名 + 行业模板/自助/AI；不碰成交金额。  
5. **微站/官网/消费者首页** = 同一首页，不同模板样式。

---

## 4. 学什么 / 禁止什么

| 采用 | 禁止 |
| ---- | ---- |
| 成熟入口/LBS/店页/App 首页交互习惯 | 自建交易、收款、销售闭环 |
| 统一入口分流、工作流整合 | 与美团/抖音抢「管店/卖货」 |
| 外链聚合（含扫呗） | 假接第三方实时库存价格当自营商城 |
| 痕迹分析与 AI 解读 | 伪造成交与资金数据 |

---

## 5. 施工纪律

1. 新需求先过 §0 过滤器：是入口/整合/工作流/痕迹分析吗？碰钱/销售/管店吗？  
2. UI 套用成熟习惯；底盘保留 ONEDAY 多租户与工作流。  
3. 不代签验收；不宣称已是美团或全部商用。  
4. 深度优化按连动：开通可见 → 附近 → 店页/模板 → 跳转痕迹 → 商圈页 → 分析看板。
