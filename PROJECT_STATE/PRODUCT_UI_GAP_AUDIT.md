## 结论（先说清楚）

**当前状态：TECHNICAL PASS，但 PRODUCT EXPERIENCE HOLD。**

技术与经营闭环（会话、租户隔离、消费者动作 → 归属/任务 → 员工跟进/证据 → 管理可见 → 审计/Outbox）已通过 Hardening / PRE-PILOT-POLISH，可做受控真人试用。

但相对已冻结产品形态——“统一经营入口 + 外部平台连接（不替代美团/抖音）+ 简单高级低学习成本”——真实 UI 仍明显偏：

1. **演示/工程后台感**（测试文案、英文任务名、无全局导航壳、登录页几乎裸 HTML）；
2. **门店经营页不完整**（缺电话、营业、图片、地图导航、团购外链入口）；
3. **支付宝式多宫格经营壳未实现**（员工端尤其明显；消费者 `action_grid` 只是不可点推荐条）；
4. **美团/抖音等外链能力“后端有、经营配置面弱、真人场景未铺齐”**。

本轮禁止扩大为自研支付/商城/收银/完整 CRM。整改目标是**恢复已定产品形态**，不是重做 ONEDAY。

### 最小正式方案（不接 SDK）

1. Store 公共读模型增加 `latitude`/`longitude`（或复用 `merchant_locations`），管理端可维护地址+坐标。
2. 门店页地址旁增加「导航」：优先 `https://uri.amap.com/...` / Apple Maps / 系统 geo URI；无坐标时用地址文本搜索 URL。
3. 点击前写一条 `consumer_action`（source=`store_map_nav`，保留 tenant/store/shareCode）。
4. Playwright：门店 → 导航 → 断言 outbound URL 与事件落库。  
   **不需要**内嵌地图 SDK。

# 报告分节（A–M）

## A. 与已定产品方案一致的部分

1. 不替代美团/抖音；外链/口令/人工回执边界诚实（PILOT_LIMITATIONS / connectors intent-only）。
2. 四端角色分工框架存在：Consumer 公共入口、Employee 执行、Management 监督配置、Platform 租户/模板/连接器/渠道商圈。
3. 经营闭环可演示：消费者动作 → 来源/归属/任务 → 员工跟进证据 → 管理可见（AUDIT-BATCH-2/6/7）。
4. 外部动作模型 `link | mini_program | platform_entry` + 协议安全校验（CORE-009）。
5. Discovery 三模型分离（渠道 / 固定商圈 / LBS）且门店深链可点（PRE-PILOT A-1）。
6. 消费者入口底栏真实可跳（A-2）；平台根进 dashboard（A-3）。
7. 移动底栏数量未超过 5。
8. 明确不做自研商城/支付/收银/开放插件市场——代码未滑向这些方向。

## B. 明确偏离的部分

1. **「多宫格快捷经营壳」被做成只读「商家推荐」+ 独立行动列表**（消费者）；员工端连可点底栏都没有。
2. **Connectors 授权页被当成「插件」主叙事**，而不是「进入美团/抖音等真实经营场景的入口」。
3. **PRE-PILOT 导航 = 路由连通**，被误认为产品导航体系完成。
4. **门店页咨询可直跳 URL**，与入口「确认页留痕」路径不一致，经营体验不统一。
5. **页面文案/任务标题偏工程与测试**（LOCAL HUMAN PILOT、Follow up…、Audit Batch…），偏离「简单高级」经营语言。
6. **管理/平台无全局经营导航**，依赖记 URL —— 工程后台感。

## C. 明确缺失的部分

1. 门店电话、营业时间、图片/封面。
2. 门店地址 → 外部地图导航 CTA + store geo 出参。
3. 团购/第三方平台聚合展示（卡片 + 平台标识 + 外跳）。
4. Management 外链（美团/抖音/饿了么/京东等）可视化配置与门店/权益绑定 UI。
5. 可配置/可排序快捷宫格 + 搜索 + 全部应用。
6. 员工真实底栏路由；场景化插件槽（非孤立插件中心）。
7. 门店页分享、推荐员工展示。
8. 消费者统一壳（发现/门店仍保持租户底栏）。
9. 域名级 URL 白名单（仅有协议级）。
10. 可视化装修 `action_grid`（page-builder 只能预览模块类型）。

## D. 仅仅没做测试的部分

1. 已有 `link` 外跳 + shareCode 归因的**专用** Playwright（现有多为咨询/`platform_entry` 或本地假 URL）。
2. 分享落地 → 门店 → outbound 的端到端来源字段断言（部分 HTTP 有，UI 旅程不足）。
3. 管理归因页对 `external_platform` / 外链动作的业务语言回归。
4. 员工侧「由分享带来的外部动作」可读性断言（后端任务存在，UI 专用断言缺）。
5. 门店与入口两条 outbound 路径的一致性回归。

（地图/电话/团购卡本身属于 C，不是“有功能没测”。）

## E. Consumer 缺口

- 无多宫格启动器；推荐不可点进门店/动作。
- 门店缺电话/地图/图片/营业/团购/分享。
- 底栏不贯穿子页；无「我的」。
- 真人 seed 无美团/抖音 link，无法演示桌码→第三方下单场景。
- 视觉：试用说明书感强。

## F. Employee 缺口

- 底栏装饰不可导航。
- 无宫格/搜索/全部应用/场景插件位。
- 外部行为归因可视性弱（只有泛化任务与 share 打开计数）。
- 登录/工作台仍偏 demo（截图与 PAGE-E 证据）。

## G. Management 缺口

- **不能在 UI 配置**消费者外链；只能看 entryCount / connectors 意图。
- 不能编辑门店电话/坐标/营业/图片。
- page-builder 无宫格可视化装修。
- 归因有，但缺「第三方团购点击」经营视图。
- 无侧栏 IA；登录页极简工程风。

## H. Platform 缺口

- 角色能力基本齐（租户/模板/连接器/渠道/商圈/审计）。
- 缺口在体验：中英混排、工程指标、无产品壳；不阻塞经营闭环，但拖累「高级低学习成本」观感。

## I. 地图/导航缺口

- **缺前端入口 + 门店详情 geo 字段衔接**；Discovery 有坐标但不导向航。
- 最小方案见第三节；不接 SDK。

## J. 美团/抖音/团购/外链缺口

- API 能力 > 管理配置 UI > 消费者团购产品面 > 真人数据样本。
- 最薄闭环缺口：Management 配置 link → 门店/入口展示团购卡 → 确认跳转 → 归因可见。

## K. 「多眼快捷宫格」缺口

- 未实现支付宝式可配置宫格。
- 现有 `action_grid` = 只读推荐；与「快捷入口进经营场景」目标不符（方向偏差）。

## L. UI 视觉和交互缺口

- 四端缺统一壳与设计令牌落地。
- 图标/图片弱；卡片过多处为信息容器而非交互必要。
- 空状态有；弱网/离线弱。
- 登录页（E/M/P）相对业务页明显更「未产品化」。
- 消费者/员工英文与「测试/模拟」文案破坏信任感。

## M. 推荐给 Codex 的一次性批量整改方案

按优先级；**禁止**自研支付/收银/商城/自动私聊/硬接 LLM/大规模重写。

### P0 — 产品方向错误（必须先纠偏认知与最小产品面）

1. **冻结表述写入整改任务：** 团购/外链 = 平台入口聚合，不是自研团购；Connectors ≠ 消费者团购入口。
2. **Consumer `action_grid` 纠偏：** 推荐卡必须可绑定 `store` 或 `external_action`；无绑定则保持只读但不可再暗示「经营快捷方式已完成」。
3. **统一 outbound 路径：** 门店/服务外跳一律经 `/c/actions` 确认留痕（与入口一致），禁止静默直跳。
4. **去掉/隔离测试口吻进入试点文案规范**（至少非 seed 环境不展示 LOCAL HUMAN PILOT 工程句）。

### P1 — 真人试用前必须补

1. **Management「外部入口配置」页：** CRUD `external_actions`（link/美团/抖音/饿了么/京东等名称+URL+平台）；绑定门店/权益；列表预览。
2. **门店经营六件套最小集：** 电话（`tel:`）、地址可点导航（第三节方案）、营业时间文本、一张封面图、咨询、≥1 个第三方入口卡。
3. **团购/外链卡片：** 标题、价格/卖点一行、平台名、点击→确认→跳转→审计。
4. **Employee 底栏改为真实 Link**（工作台/客户或线索/提醒或消息/我的），仍 ≤5。
5. **Playwright 真人剧本：**  
   Discovery→门店→电话；门店→地图 URL；门店→美团 link；分享码→门店→外链→attribution；员工看到任务；老板在归因看到来源。
6. **Pilot seed 增加 1 条美团模拟 https link + 1 条抖音模拟 link**（仍可不接真 API）。

### P2 — V3.1

1. 支付宝式可配置宫格（排序、搜索、全部应用、插件场景槽进现有页）。
2. 四端共享导航壳 + 设计令牌落地（承接 `V3_1_DESIGN_DEBT.md`）。
3. 域名白名单与租户级允许主机。
4. page-builder 可视化编辑 `action_grid`/content。
5. 员工「外部行为」时间线；管理「渠道×平台」外链漏斗。
6. 消费者底栏租户可配置中间项 + 贯穿子页壳。

### P3 — 后续

1. 小程序 SDK 真跳（现口令策略可保留为降级）。
2. 多图相册、营业状态自动切换、地图选点采坐标。
3. 更细的平台品牌组件库（美团/抖音视觉规范授权前提下）。
4. 弱网/离线与视觉回归基线扩展。

### 建议 Codex 执行批次（一次批量，仍禁止范围膨胀）

**Batch PE-1（P0+P1 核心，约一个整改波次）：**  
外链配置 UI + 门店六件套字段/展示 + 团购卡 + outbound 路径统一 + 员工真底栏 + 对应 Playwright + pilot seed 两条外链。

**Batch PE-2（P2 壳层）：**  
宫格启动器 + 四端壳 + page-builder 编辑 + 域名白名单。

不要与 Hardening/安全专项混谈；本专项验收标准是**产品形态恢复**，不是再刷测试计数。
