## 0. 给 Codex 的一句话结论

**核心经营闭环（场景进入 → 来源/归属 → 员工任务 → 跟进证据 → 管理可见）已可真实跑通，与“AI 经营操作系统 / 统一数字入口”定位一致，未滑向商城/支付/外呼/自动外发。**

当前主要缺口是：

1. **消费者发现与入口导航断点**（能看不能点进经营动作）；
2. **AI 能力面与文案诚实度不齐**（管理端有受控落地；消费端“AI 推荐”是模板卡片；`ai-core` 包空壳）；
3. **冻结业务规则中部分高级规则未实现**（扫码 2 分钟无动作提醒、离职 AI 交接任务、标签置信度衰减等）；
4. **防御与运维债**（无 RLS、Redis 虚依赖、refresh pepper、平台指标 SQL、Outbox 空 handler）；
5. **人类试点门禁仍未签字**（种子账号事故面）。

优化应优先 **补全入口连续性与话术校准**，禁止借机做支付/CRM/自动发帖等 **OUT_OF_SCOPE** 扩张。

## 1. 产品定位对照（Codex 决策边界）

### 1.1 定位（必须守住）

- ONEDAY = **企业 AI 经营操作系统 + 统一数字经营入口**
- 连接：消费者流量、员工执行、老板经营、渠道/商圈
- 原则：能跳转先跳转；能回写再连接；不替代美团/抖音/企微等；关键动作留痕

### 1.2 明确不做（优化方案禁止滑入）

支付/收银、完整 CRM/ERP、外呼、多级分润、OEM 市场、任意低代码、**未授权自动私聊/发朋友圈/平台发布**。

### 1.3 MVP 成功判断 1–7（本轮实测映射）

| #   | 要求                         | 实测                                                  | 判定         |
| --- | ---------------------------- | ----------------------------------------------------- | ------------ |
| 1   | 场景码进商户并执行动作       | Entry → `/c/actions` 可确认；B7 PASS                  | **满足**     |
| 2   | 记录来源/场景/员工/商户/行为 | Orchestrator 同事务投影                               | **满足**     |
| 3   | 未完成动作 → 员工任务        | 有 share/店长则建任务；否则进 lead-pool（不伪造指派） | **满足**     |
| 4   | 员工跟进并上传证据           | B7 真实登录 + result/evidence                         | **满足**     |
| 5   | 管理者看过程/异常/归因/结果  | B7 management trail + hardening-002                   | **满足**     |

| 7   | 渠道/商圈开通并查看运营      | channel-002 / circle-002 HTTP PASS；平台壳首页仍占位  | **基本满足** |

### 2.2 模拟“真人使用”的链路结论

#### 链 A — 主商业闭环（关键路径）

```text
公开消费者动作(tenant+shareCode)
 → 经营投影(customer/source/ownership/task)
 → 员工真实登录 → 跟进/结果图证/完成
 → 老板真实登录可见
 → 跨租户/未分配员工 404
```

**结论：可演示、可试点。** 与定位一致。

#### 链 B — 员工/管理/平台会话

真实 login（租户 slug）→ 工作 → access 过期 refresh → logout 旧 token 拒绝；消费者无后台登录墙。

**结论：通过。**

#### 链 C — 发现与入口导航（断裂）

- `/c/discovery`：渠道/商圈/附近商户 **仅展示名称，无链接到** `/c/entry` 或 `/c/stores/[id]`。
- `/c/entry` 底栏「首页/发现/权益/咨询」与「AI 推荐」卡片：`setActive` **只改高亮，不跳转**。
- 消费者主路径 **看不到** `/c/processes`、`/c/profile` 入口（过程查询靠独立 secret）。

**结论：HTTP/数据层可用，真人“逛发现 → 进店 → 行动”不连续。** 属定位内缺口，不是要做商城。

#### 链 D — AI

- 管理端：有建议列表与受控执行（白名单本地建任务）。
- 消费端：「AI 为你推荐」实际是模板 `action_grid.recommendations`。
- 员工端 / 渠道端：无独立 AI 建议面。
- `packages/ai-core`：仅包名常量，无运行时推理。

**结论：MVP #6 管理侧部分成立；文案与 must-deliver「AI 消费者推荐」存在诚实度/范围张力。**

#### 链 E — 渠道/商圈

开通、双审批、展示控制 HTTP 可证；平台根页仍写“后续接入”，易误导试点操作员。
